Assigned Algorithm Specifications

Allotted: Algorithm 2 (DFS)

Depth First Search is an uninformed graph search strategy that systematically progresses down deep branches of the search space before exploring sibling paths. This page details all eight required theoretical criteria evaluated in the course curriculum.

1. Description

Depth First Search (DFS) begins at the root state and explores as deeply as possible along each branch before backtracking. In this web application, DFS is implemented from scratch using native JavaScript and runs within a dedicated Web Worker to avoid freezing the browser user interface.

2. Working Principle

DFS utilizes an explicit Last-In, First-Out (LIFO) stack for its frontier. Nodes are expanded from the top of the stack. When the search encounters a state with no new successors or an already-explored state, it backtracks to the most recent predecessor possessing unexpanded children. An explicit visited set (Closed List) provides cycle detection to prevent infinite loops.

3. Deterministic Successor Order

To ensure deterministic and inspectable search behavior, blank tile moves are strictly generated in the order: Up, Right, Down, Left. Successors are checked against the visited set before pushing to the frontier stack.

4. Advantages

The foremost advantage of DFS is its **minimal memory requirement**. Storing only the path from the root to the current node plus unexpanded sibling nodes requires only $\mathcal{O}(bm)$ space, which is negligible compared to Breadth First Search ($\mathcal{O}(b^d)$). When lucky enough that the goal resides along an early deep branch, DFS finds a solution rapidly.

5. Limitations

DFS is **non-optimal** and frequently returns long, convoluted solution paths even when a short solution exists. Without cycle detection, it can become trapped in infinite loops. Worst-case time complexity is exponential, as it may explore vast irrelevant subtrees before backtracking.

6. Complexity Analysis

Time Complexity: $\mathcal{O}(b^m)$, where $b$ is the average branching factor ($b \approx 3$ for the 8-puzzle) and $m$ is the maximum depth reached in the search tree.

Space Complexity: $\mathcal{O}(bm)$, linear in maximum depth $m$. It only stores nodes along the active branch and unexplored siblings on the frontier stack.

7. Completeness

DFS is complete on finite state spaces with cycle detection (visited set). In infinite search trees or without visited tracking, it is incomplete as it may follow infinite non-goal paths.

8. Optimality

DFS is non-optimal. The algorithm halts immediately upon encountering the first goal node, which is determined strictly by stack order rather than minimal step cost.

Algorithm Pseudocode (Iterative Graph-Search DFS)

function GraphDFS(initialState, goalState, expansionLimit):
    frontier = new Stack()
    visited = new Set()
    
    frontier.push({ state: initialState, depth: 0, parent: null, move: null })
    visited.add(initialState.key)
    
    while frontier is not empty:
        if expandedCount >= expansionLimit:
            return LimitReached
            
        current = frontier.pop()
        
        if current.state == goalState:
            return ReconstructRoute(current)
            
        expandedCount += 1
        
        // Successors in deterministic order: Up, Right, Down, Left
        for action in [Up, Right, Down, Left]:
            if action is legal for current.state:
                successor = ApplyMove(current.state, action)
                if successor.key not in visited:
                    visited.add(successor.key)
                    frontier.push({ state: successor, depth: current.depth + 1, parent: current, move: action })
                    
    return ExhaustedNoSolution
